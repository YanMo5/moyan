## 1. P0 阻断级

### P0-1【已处理 2026-11-26 11:16】两个 Node 实例同时运行，共享同一个 SQLite 和会话文件

**证据**

- 3000 与 3100 都能响应：/api/stats 均返回 200。
- 3000 是旧版本：GET /api/admin/visitors 返回 404；3100 返回 401（有该路由）。
- 两边使用同一个 data/blog.db（db mtime 持续变化），SQLite 没有配置 busyTimeout / WAL。
- data/server.out.log 显示 rss-poller 每 15 分钟成功「updated 2」——它实际写的是 3000 那个旧实例（rss-poller 的写死端口见 P1-5）。
- data/admin-sessions.json 由 3100 写入，但两个实例各自持有内存会话表；在 3000 上登录的会话与 3100 不互通。
- 文件 mode 为 666（Windows 上 mode 不生效，Linux 上需 600）。

**风险**

并发写 SQLite 可能出现 SQLITE_BUSY / 丢写；会话文件被两个进程覆盖；旧实例缺少新接口，行为不一致。

**处理结果（2026-11-26 11:16）**

- 已停止 3000（旧版，PID 31988），只保留 3100（PID 26880）。
- netstat 确认仅 3100 LISTENING；3000 已无监听。
- 仍未开启 WAL/busy_timeout（单实例下不急，建议后续补上）。

### P0-2 Git 工作区与仓库严重脱节，核心文件未跟踪

**证据（git status）**

- 未跟踪但被页面直接引用的文件包括：src/css/aurora.css、legal.css、tools.css、src/js/taxonomy.js、tools-page.js、src/pages/categories.html、daily.html、privacy.html、policy.html、rss.html、stats.html、tags.html、tools.html、version.html、lib/moderation.cjs、lib/rate-limit.cjs、lib/validation.cjs、src/data/tools.json 等。
- assets/icons、assets/video、assets/images/og-cover.png、scripts/set-smtp-pass.ps1、docs 备份也全部未跟踪。

**风险**

如果使用 Vercel 的 Git 集成部署，线上拿到的只是已提交的旧版本，aurora.css、多个页面和校验模块都会缺失，站点会直接坏掉。当前线上之所以正常，是因为本机工作区文件在跑，而不是仓库完整。

**建议**

1. 先 git add -A，人工检查 diff（排除 data/、_shots、_tmp、视频源等）后提交。
2. 在 .gitignore 中补齐本地垃圾（已补 _shots、_tmp、pip-*、tmp*、%SystemDrive%、undefined）。
3. 确认 Vercel 是用 Git 还是 CLI 部署；两种方式都要保证工作区完整。

### P0-3 云端 API 与本地 API 严重不一致，Vercel 后台大面积不可用

本地 server/server.js 有，但 api/[...route].js 没有：

| 功能 | 本地 | 云端 |
| --- | --- | --- |
| 工具库 /api/tools CRUD | server.js:1950-2050 | 无 |
| 相册 /api/albums | server.js:1600-1750 | 无 |
| 后台友链统计 /api/admin/links | server.js:1250 | 无 |
| 后台访客 /api/admin/visitors | server.js:1261 | 无 |
| 留言已读 PATCH /api/messages/:id | server.js:1208 | 无（只有 DELETE） |
| 留言回复 /api/messages/:id/reply | 无 | 无 |

同时，云端 messages 表没有 is_read / subject / source 字段（api/[...route].js:224-231），links 表没有 category / is_online / latest_post_*（233-241），daily_posts 没有 album_id（254-259）。

**影响**

- 后台「工具库」「日常相册」「访客统计」「留言已读」「友链统计」在 Vercel 上会 404 或空白。
- 前台「日常」页调用 /api/albums，云端会显示「相册集暂时不可用」。
- 前台工具库会回退到静态 tools.json，但后台修改不会生效。

**建议**

二选一：
1. 在云端补 tools/albums/visitors/PATCH 路由与表结构；
2. 明确「这些功能仅本地 Node 可用」，前端在 404 时隐藏对应模块，不显示报错。

### P0-4 友链探测与留言回复在两端都不可用

友链探测：
- src/pages/links.html:514 直接 POST /api/check-links，没有带 X-CSRF-Token。
- 本地 server.js 没有 /api/check-links 路由，实测 404。
- 云端 api/check-links.js:300-308 现在要求管理员会话 + CSRF，前端不满足，必然 401/403。
- vercel.json:90-93 把所有 /api/* 先重写到 api/[...route].js；/api/check-links 很可能在到达独立函数前就被 catch-all 截走（需要线上验证），即使没被截走，也过不了 CSRF。

留言回复：
- src/pages/guestbook.html:253 调用 POST /api/messages/<id>/reply。
- server/server.js 与 api/[...route].js 都没有这个路由；页面上的「回复」按钮必然 404。

**建议**

- 友链探测：把探测逻辑并进 catch-all，或调整 vercel.json 路由顺序并为前端补 CSRF 头（仅管理员登录后显示探测）。
- 留言回复：要么实现 message_replies 表 + 回复接口，要么隐藏回复 UI，避免死按钮。

### P0-5【已处理 2026-11-26 11:16】SMTP 已配置但运行进程没有加载，邮件通知仍不可用

**证据**

- 直接用 lib/mailer.cjs 的 verifyTransport() 测试：{"ok":true}（账号可登录）。

**结论**

配置本身没问题，只是运行中的进程在 .env 写入之前启动。重启服务后邮件通知即生效。

**处理结果**

- 已重启 3100；日志首行出现「[env] 已加载 F:/BoKe-main/.env」，server.err.log 为空，不再出现「邮件通知未配置」。
