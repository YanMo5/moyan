关于我 / WHOAMI 最近校对 2026.11

我的方向集中在三块：Web 应用安全（OWASP Top 10、漏洞复现与修复验证）、 企业安全运营（日志狩猎、零信任落地、应急响应），以及 AI 安全（Prompt Injection、RAG 数据泄露、模型供应链风险）。 比起堆工具，我更在意一条完整链路能否被解释清楚。

最早是从写 Python 脚本做自动化开始接触安全的。后来慢慢发现，「打得动」不等于「讲得清」—— 于是开始把每个靶场、每个 N-day 的复现过程整理成文章，逼自己把利用条件、影响面、 检测思路和修复方案都写完整。这也是我判断自己是否真的学会的标准。

这个站点是我自己从零搭的：静态前端 + Express / SQLite 后端 + SMTP 邮件通知 + Vercel 部署。 写博客本身也是一次安全工程实践——输入校验、CSRF、限流、上传与日志，这些坑都是真实踩过的。 站内所有实验均在自建环境或授权范围内完成。

// 0x06 · PRINCIPLES

协作原则 / PRINCIPLES 写文章与做实验的底线

P-01

先授权，再动手

只在自建环境或书面授权范围内测试。文章里的演示数据、域名与日志均来自实验环境，不做无授权探测。

P-02

复现要能回滚

记录版本、配置、payload 与修复前后的对比，让别人按笔记能重跑一遍；不能复现的过程不算结论。

P-03

结论要有证据

不写「可能存在」这类模糊判断，给出请求响应、日志片段或截图，并明确标注仍未验证的部分。

P-04

修复优先于炫技

能落地的加固方案（配置、检测规则、代码修复）比利用链本身更值得写，也更容易被别人复用。

站内的文章可以转载吗？
可以，请保留作者信息并注明出处与原文链接，不要拆分或曲解原意。 商业用途或整站搬运请先发邮件沟通。
会接渗透测试或安全评估吗？
目前以学习和授权项目为主。可以邮件说明测试范围、目标类型与时间窗口， 我再判断是否合适；没有书面授权的目标一律不接。
靶场环境能分享吗？
环境都基于公开镜像搭建，编排与配置脚本整理在 GitHub。 涉及具体练习目标的配置不会公开，避免影响他人的解题体验。
文章里的利用代码该怎么用？
仅限授权测试与教学环境。对未授权目标使用造成的一切后果由使用者自负， 本站不提供任何针对真实目标的攻击支持。
发现文章有错误，或者想补充内容？
欢迎通过邮件或 GitHub issue 指出， 附上复现步骤或依据即可；核对后我会更新正文并在文末注明修订。
